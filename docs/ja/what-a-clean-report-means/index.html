Markdownの「問題なし」で分かること、分からないこと

kolmo2026 · 運営について

公開 2026-11-03 · 更新 2026-11-04

エラー0は、対応する機械的な点検で問題が見つからなかったという意味です。論文の正しさ、引用の網羅性、数式変換の完全性を示すものではありません。この境界を明確にして使う方が、報告を役立てられます。

コードは本文として診断しない

mdast-util-from-markdownでMarkdownを構文木に変換します。フェンスコード、字下げコード、インラインコードの中は、見出しやリンクの診断対象から除外します。コード内で![missing](figure.png)を例示しても画像は必要ありません。ドル記号そのものは一切診断しません。数式区切りを検証しないため、価格やシェル変数を壊れた数式と扱うこともありません。

閉じていないコードフェンスはエラーとして扱います。CommonMarkでは終端まで続くフェンスも許されますが、研究作業では後続の本文を誤って取り込んだ可能性があるためです。修正する前に原文を確認してください。

パスの確認は巡回ではない

相対パスはシェルの現在位置ではなく、Markdownファイルのあるディレクトリから解決します。パーセントエンコードした名前を復号し、ファイル確認時にはフラグメントとクエリーを取り除きます。絶対ファイルパスもローカルのファイルシステムで解釈します。外部スキーム、プロトコル相対URL、フラグメントだけのリンクは対象外で、外部URLを取得することはありません。画像内容や見出しアンカーの存在も確認しません。

参照記法と終了コード

定義済み参照リンクはパーサーが認識した定義を使います。未定義の[Dataset][data]のような明示的形式はテキスト節から検出します。[Dataset]のような短縮形式は普通の角括弧付き文章と区別できないため、未定義チェックをしません。複雑なエスケープ付き括弧は目視で確認が必要な場合があります。

node src/cli.js paper.md --json
# 0: エラーなし（警告は残る場合あり）
# 1: 構造エラーあり
# 2: 呼出し方法またはファイル読取の問題

ローカル研究スクリプトではコード1で処理を止めつつ、見出しの飛びを警告として扱えます。npm testでコード内見出し、インラインリンク、日本語ファイル名、ファイルパスの判定例を確認できます。ツールは読み取り専用で、報告を「問題なし」にするために原文を自動修正することはありません。

元資料がまだPDFなら、ローカル点検の前にKolmoPDFでPDFをMarkdownに変換する方法があります。クラウドサービスで、文書をアップロードして処理します。このチェッカーはそのパーサーを含まず、変換で科学的な細部がすべて保持されたと証明するものでもありません。
